## 🎯 一、教具擴充開發全貌架構（Teach Tools Architecture）

全站教具專區位於 `/teach/` 路徑下，採用高響應式（Mobile RWD）、長輩友善（高對比、大觸控面積）、高權重 SEO（Schema.org FAQPage、WebApplication、BreadcrumbList）設計：

```
teach/
├── index.html            # 互動衛教教具首頁（9 大教具地圖與導航總覽）
├── cook-database/        # 料理影片資料庫（275 部公信力示範食譜、電鍋專區、AI提問、單頁列印）
│   ├── index.html        # 資料庫前端主介面（支援搜尋、標籤篩選、國臺語切換彈窗、列印隔離）
│   └── recipes_full.json # 結構化真實料理資料庫（120 部高精準食材步驟 + 155 部誠實引導提示）
├── daily-needs/          # 熱量與三大營養素計算機（TDEE/BMR、高齡肌少症蛋白質、三大營養素配比）
│   └── index.html
├── food-exchange/        # 食物代換速查表（六大類總表置頂、折疊下拉選單、無障礙三欄表格）
│   └── index.html
└── ox-challenge/         # 長者認知與防跌 O/X 互動教具（長照雙重任務訓練、大字體大按鈕）
    └── index.html
```

### 1. 料理影片資料庫 (`teach/cook-database/`)
- **公信力收錄原則**：專注收錄「衛生福利部國民健康署」、「各縣市衛生局」、「各縣市社區營養推廣中心」、「各大醫學中心營養部」及「癌症希望基金會」、「腎臟病防治基金會」之官方食譜。
- **功能設計**：
  - **核心操作按鈕**：僅保留「▶ 看影片」、「📋 複製提問」、「🖨️ 列印教案」，介面極簡乾淨。
  - **雙語雙向跳轉**：針對各衛生局錄製之國語與臺語影片，料理名稱明確標註【國語版】與【臺語版】，並在彈窗提供一鍵雙向切換。
  - **真實食材步驟展示**：具備手冊或字卡驗證之 120 部料理完整展示精確克數與電鍋烹調；其餘影片呈現誠實引導卡片，點擊一鍵複製 AI 提問詞，讓 AI 依現場人數精確換算。

### 2. 熱量與三大營養素計算機 (`teach/daily-needs/`)
- **精準營養邏輯**：三大營養素（蛋白質、碳水化合物、油脂）數值為全日總量建議，**嚴禁標註單一食物份數**（例如不可標註「等於9份豆魚蛋肉類」或「等於2.8碗熟飯」），總量來自各大類食物之綜合貢獻。
- **SEO 結構化資料**：內嵌 `FAQPage` 解答 TDEE/BMR 原理、高齡蛋白質增肌需求與熱量赤字安全設定。

### 3. 食物代換速查表 (`teach/food-exchange/`)
- **命名簡潔**：正名為「食物代換速查表」。
- **介面配置**：最上方置頂保留衛福部官方六大類食物代換總表圖；下方各分類下拉選單**預設一律收合**；三欄自適應表格（食物名稱、份量說明、可食生熟重）。

### 4. 長者認知防跌 O/X 挑戰 (`teach/ox-challenge/`)
- **雙重任務設計**：結合記憶、營養知識與肢體反應，適合長照據點活動帶領，按鈕大、文字大。

## ⚠️ 二、重大錯誤復盤與避坑指南（Lessons Learned & Pitfalls）

### 🚨 避坑 1：嚴禁推測原則（Zero-Guesswork Rule）——杜絕假模板文字
* **錯誤教訓**：在料理資料庫初期，為填補材料與步驟欄位，使用了模板化字串（如「某某主食材適量」、「放入容器熟化」等通用文字）。這嚴重破壞了內容真實性與使用者信任！
* **規範守則**：
  - 凡涉及食材克數、匙數、烹調時間與醫學數據，**未取得原始資料前絕不臆測生成**。
  - 尚未完成手冊對齊或資訊欄未載明精確克數的影片，**嚴格標示誠實指引**：「請點擊下方【看影片】觀看原頻道完整示範；或點擊【複製提問】一鍵生成精確材料與步驟指引！」，絕不放任何虛構假資料。

### 🚨 避坑 2：公信力影片去重與雙語版本辨識
* **錯誤教訓**：匯入臺中市衛生局「健康小衛星」播放清單時，因該清單每一道菜均錄製了「國語」與「臺語」兩支影片，若未分辨語言直接以同菜名匯入，會造成清單中每道菜重複出現兩次。
* **規範守則**：
  - 先剔除形象宣傳短片（非食譜操作影片）。
  - 在料理名稱部分明確標註「【國語版】」與「【臺語版】」（例如：《台式瑪格莉特披薩【國語版】》與《台式瑪格莉特披薩【臺語版】》）。
  - 彈窗內建立雙向切換按鈕（「🗣️ 切換至【臺語版】教學影片」），提供長者親切選擇。

### 🚨 避坑 3：單頁列印樣式隔離（@media print）
* **錯誤教訓**：點擊「列印教案」時，因缺乏 `@media print` 樣式隔離，瀏覽器將全網頁背景與 200 多張料理卡片全數印出，造成列印內容無限重複與版面破裂。
* **規範守則**：
  - 必須設定 `body.print-single-mode > *:not(.recipe-modal-overlay) { display: none !important; }`。
  - 列印時將彈窗定位設為 `static`，移除背景遮罩與功能按鈕，確保 100% 乾淨輸出單一教案卡片。

### 🚨 避坑 4：深色橫幅文字對比（Hero Banner Contrast）
* **錯誤教訓**：全域樣式 `styles.css` 中 `.lead` 被定義為暗灰色（`#405064`），覆蓋了深綠色 Hero Banner 內的文字，導致深底深字無法閱讀。
* **規範守則**：
  - 在全域 `styles.css` 與頁面中強制宣告 `.hero-banner, .hero-banner * { color: #FFFFFF !important; }`，徹底防範全站深底暗字問題。

### 🚨 避坑 5：AI 提問 Prompt 的定位
* **錯誤教訓**：曾誤將「複製提問」改成現場帶長輩聊天的「課堂提問」，失去 AI 輔助的價值。
* **規範守則**：
  - 「複製提問」的定位是：讓使用者/講師直接複製貼給 ChatGPT/Gemini/Claude，要求 AI 將材料換算為「10 人份」、列出小孩長輩都懂的步驟、分析各疾病（三高腎臟痛風）注意事項與防嗆活動安排。

## 💡 三、使用者核心偏好與設計哲學（User Preferences & Design Philosophy）

未來的 AI 助理（Antigravity / Codex）在進行任何討論與開發時，必須直接遵循使用者的以下特殊喜好：

1. **版面純淨沉穩，拒絕過度花俏**：
   - 喜歡乾淨、俐落、好閱讀的版面。
   - **配色偏好**：回歸網站預設的沉穩深綠與白色，**嚴禁用刺眼的大橘色或過度花俏的裝飾**。
   - 料理卡片上方必須呈現清晰的影片縮圖（YouTube mqdefault.jpg），方便一眼辨識。

2. **精簡功能按鈕，杜絕花俏冗餘**：
   - 不需要「✨ 複製並開 Gemini」、「⚡ 一鍵帶入 Google AI Studio」等多餘功能按鈕。
   - 核心功能只需三者：**「▶ 看影片」**、**「📋 複製提問」**、**「🖨️ 列印教案」**。
   - 不需要右上角複雜的「我的最愛」匯出/匯入按鈕。

3. **極度重視「電鍋食譜」與「無明火安全」**：
   - 長照課堂與高齡自煮極為重視「電鍋料理」與「零明火操作」。
   - 若能擴充電鍋料理、標明外鍋水杯數、燜煮時間與低鈉提鮮技巧，列為最高優先級。

4. **公信力單位至上，非公信力不可混入**：
   - 篩選標籤選擇「國健署」或「社區營養」時，**嚴禁混入私人頻道**。
   - 專注收錄：衛福部國健署、各縣市衛生局、各縣市社區營養推廣中心、各大醫學中心營養部、癌症希望基金會、腎臟病防治基金會。

5. **長輩無障礙與手機（Mobile RWD）閱覽舒適度**：
   - 大字體、高對比、大觸控點擊面積（按鈕高度至少 44px-48px）。
   - 手機螢幕下必須流暢單欄滿版，彈窗全螢幕滑動，杜絕任何橫向捲軸溢出。

6. **全站 SEO 與 AI (GEO) 知識庫無縫同步**：
   - 所有教具網頁必須埋入完整結構化資料（Schema.org `FAQPage`、`BreadcrumbList`、`WebApplication`）。
   - 每次新增或更新頁面，必須同步執行 `python tools/sync_seo_and_geo.py` 更新 `sitemap.xml`、`sitemap.html`、`robots.txt`、`llms.txt` 與 `llms-full.txt`。

7. **本機 D 槽與 GitHub 遠端 100% 即時同步**：
   - 作業完成後必須安全清理臨時過程檔（移至資源回收桶），執行 `git status` 確認 clean，並推上 `origin main`。
